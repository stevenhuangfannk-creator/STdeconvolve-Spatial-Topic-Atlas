# 扩展方法说明 / Extension methods

以下三个模块属于本项目的分析设计。它们读取已完成的官方核心复现对象，不改变核心预处理、原始注释、Theta/Beta 或其他 Figure。实际执行状态以根目录 `FINAL_REPRODUCTION_REPORT.md` 和各输出表为准；存在脚本不等于已经完成分析。

## 共同输入与运行 / Inputs and execution

从仓库根目录使用 R / VS Code R Interactive：

```r
source("05_Functional_Enrichment.R")
source("06_Multi_Sample_Analysis.R")
source("07_Spatial_Neighborhood.R")
```

三个脚本均首先读取 `00_Start.R` 和 `data/processed/core.rds`。所需对象包括 `counts`（gene × spot 原始整数计数）、`pos`（spot × x/y）、`theta_raw`（spot × Topic，未使用显示阈值截断）、`beta`（Topic × gene）、`beta_scale`、`selected_k`。`beta / beta_scale` 是模型中给定 Topic 的基因概率，不能当作独立观测的基因表达量做差异表达检验。

依赖按 `environment/install_dependencies.R` 明确安装；脚本不会自动安装包。所有模型和置换串行执行。图件通过统一 helper 导出白底 PNG（300 dpi）、PDF、SVG，使用同一 stem；各脚本末尾保存时间和 R 堆内存记录。该内存记录不等于整机或所有子进程的峰值 RSS。

## Figure 05：功能富集 / Functional enrichment

### 目的与数据

该模块询问：某个 Topic 相对于其他 Topic 的基因概率分布，是否偏向特定的功能基因集？它不能检验组织内某条通路是否被因果激活，更不能替代真实实验或细胞类型注释。

物种固定为小鼠 `Mus musculus`。输入基因为核心 Beta 实际包含的过度离散基因。先通过 `org.Mm.eg.db` 将标准 SYMBOL 映射到 Entrez ID；一对多和多对一映射均记录并排除，避免同一基因重复计数。不将人类通路的同名 SYMBOL 直接用于小鼠数据。

每个库使用单独背景：

\[
U_L=\{\text{实际进入 Beta 且唯一映射的基因}\}\cap\{\text{该数据库具有注释的基因}\}.
\]

背景按各库注释覆盖度变化，不使用整套小鼠基因组，也不以 marker 本身作为背景。保留与背景交集后至少 5 个基因、且不超过背景 90% 的通路。该小型示例的背景只有少量已选基因，检测能力、通路覆盖度和可泛化性受到明显限制；无显著通路是有效结果。

### 数据库与来源

| 库 | 实际读取方式 | 需要注意 |
|---|---|---|
| GO BP | `org.Mm.eg.db` 的 `GOALL`，筛选 `ONTOLOGYALL == "BP"`；`GO.db` 提供术语名称 | 包括 GO 祖先术语，通路高度冗余；版本来自实际安装包 |
| KEGG | [官方 REST 小鼠基因—通路映射](https://rest.kegg.jp/link/pathway/mmu)及[小鼠通路名称](https://rest.kegg.jp/list/pathway/mmu) | Entrez ID 与 `mmu` 物种一致；联网失败记 `BLOCKED` |
| Reactome | [官方 NCBI All Levels 映射](https://download.reactome.org/current/NCBI2Reactome_All_Levels.txt)，逐块读取后只保留第六列 `Mus musculus` | 包含计算推断的非人类事件；不等同于所有事件均被小鼠实验直接验证 |

Reactome 官方入口为[下载页面](https://reactome.org/download-data)。下载失败时不会构造替代通路。可在 `data/raw/Reactome_mouse_NCBI.tsv` 放置同一来源的六列小鼠映射，或在脚本参数中指定明确的小鼠 Entrez GMT，同时填写来源 URL 与版本。只有已通过 ID 交集检查的库参与实际计算。每个库的 `READY/BLOCKED`、文件或序列化映射 SHA256、版本与检查时间均保存到 `database_provenance.csv`。缓存是为了避免重复下载；使用已有缓存时该运行时间是检查时间，首次下载日期须结合原始获取记录判断。

### ORA 与排序方法

对 Topic \(t\) 与每个基因 \(g\)，计算：

\[
r_{tg}=\log_2\frac{\beta_{tg}/s+10^{-8}}
{\operatorname{mean}_{u\ne t}(\beta_{ug}/s)+10^{-8}},
\]

其中 \(s\) 是 `beta_scale`。该排序描述 Topic 内部模型概率的相对特异性，不是疾病—健康的 log fold change。

ORA marker 先要求概率大于 `5/1000`、且 \(r_{tg}>0\)，再按该 Topic 的 Beta 概率从高到低最多取 40 个。阈值与数量可在脚本顶部调整。对背景内每个可测通路运行单侧超几何检验；零 overlap 的通路也参与校正。若 marker 为零，不会将其当作有生物学富集证据。

GSEA 使用同一库背景中所有可靠映射基因的上述有方向排序，以 `fgseaMultilevel`、`eps=0`、`nproc=1` 运行，并保留原始 p、NES、leading edge 和误差估计。重复分值不人为加入随机抖动。最小集合 5 是对小示例的参数调整，正式数据应评估覆盖度和参数敏感性。

两类检验均在“每个 Topic × 每个数据库 × 每种检验”内对全部可测通路执行 BH。该控制范围不等于整个仓库所有 Topic/库/方法的总体 FDR；如果计划从所有结果中挑选单一结论，应预先扩大检验家族并重新校正，不能把两类检验混合挑选后仍宣称全局 FDR 5%。

### 图件与完整结果

| 输出 stem | 读图方法 |
|---|---|
| `05A_ORA_dotplot` | 每库选择诊断性通路展示各 Topic。大小为 overlap 基因数，颜色为 −log10(BH q)，实心点表示达到阈值，空心点表示未达到；可能全部不显著 |
| `05B_ORA_barplot` | 同一通路只展示 q 最小的 Topic，属于已声明的筛选展示；虚线是 q=0.05，不能用柱高代替效应量 |
| `05C_enrichment_map` | 仅显著 ORA 节点，边为同库基因集 Jaccard 相似度。环形位置用于排版，不表示生物学距离；无显著节点则明确显示空结果 |
| `05D_GSEA_pathway_heatmap` | NES 的正负表示 Topic 相对概率排序的方向，星号表示库内该 Topic BH q 达阈值；没有星号的色块不构成显著证据 |

## Figure 06：两个真实切片比较 / Cross-slice comparison

### 与官方教程的关系

[官方 Combining Datasets](https://jef.works/STdeconvolve/combining_datasets.html)展示了独立模型及合并模型，并使用 `getCorrMtx` 与 `lsatPairs` 比较 Topic。官方内置 `mOB` 对应其中 Rep8；第二个真实切片来自官方教程指定的 [Rep2 count TSV](https://www.spatialresearch.org/wp-content/uploads/2016/07/Rep2_MOB_count_matrix-1.tsv)。本项目只使用这两个实际切片，没有把一个切片拆成伪样本，也没有复现全部四个切片或合并模型实验。

为了减少计算并使特征空间完全相同，本扩展将 Rep8 核心选中的基因与 Rep2 实测、QC 后基因取交集，并去掉任一切片中全部为零的基因。Rep2 使用 `cleanCounts(min.lib.size=100, min.reads=1, min.detected=1)`。共同基因内全零的 spot 无法拟合，故单独记录排除清单。这种以 Rep8 选基因为起点的设计存在特征选择偏倚；正式跨条件研究应预先确定选基因策略并评估批次/测序深度。

两个切片均在共同基因上重新独立拟合；固定 K 为核心选择的 K，Rep8 seed=0、Rep2 seed=1。这里不为 Rep2 再搜索最优 K。因此它是受控的固定 K 示范，不能用来证明相同 K 对两个切片都最合适。

固定单 K 时，使用官方 `fitLDA` 源码中相同的 `topicmodels::LDA` 调用及 `control=list(seed=..., verbose=0, keep=1, estimate.alpha=TRUE)`。原因是官方包装函数还执行需要多 K 的 Kneed 诊断；该选择保留 LDA 引擎与参数，不替换算法。

### 匹配及解释

`getCorrMtx(type="b", thresh=NULL)` 在全部共同基因的概率上计算 Pearson 相关；`lsatPairs()` 用线性分配最大化整体相关，一对一匹配 Topic。编号是每个独立模型的任意标签，不能直接比较。

LSAP 在每个 Topic 都必须配对的约束下工作，弱甚至负相关的对应也可能被迫匹配。必须读取 `LSAP_topic_pairs.csv` 中的真实 Pearson r，并结合 marker、空间位置和独立参考判断；星号只标识匹配，不代表统计显著或已验证相同细胞类型。

`06A_cross_sample_similarity` 展示完整相关矩阵；`06B_descriptive_composition` 展示对应 Topic 的平均原始 theta；若坐标可解析，`06C_matched_spatial_topics` 展示两切片的原始空间图，不进行切片配准。坐标单位为 array 原始单位。组成比较只有每个样本一张切片，没有生物学重复检验，不应把 spot 当作独立个体做疾病—健康推断。Theta 是相对模型组成，不是绝对细胞数量。

`results/multi_sample/` 保存原始文件 SHA256、实际输入规模、共享基因、排除 spot、独立模型、参数、全部对应与组成描述表。模型缓存包含参数与输入计数哈希，参数改变时必须明确设置 `refit_models=TRUE`。

## Figure 07：空间统计 / Spatial neighborhood

### 图、统计与零假设

使用未阈值化 `theta_raw`，按原始 x/y 的欧氏距离构建每 spot 六近邻图。等距离按原始 spot 顺序打破并列。只要任一方向是近邻就保留无向边，最终使用对称二元权重、无自环，不做行标准化。该图是一种探索性邻域定义，长边不保证组织中的真实接触；坐标未经平台校准，不能标为微米。

令中心化、以样本标准差缩放的 Topic 为 \(z_{it}\)，\(S_0=\sum_{ij}w_{ij}\)。脚本报告：

\[
I_t=\frac{n}{S_0}\frac{\sum_{ij}w_{ij}z_{it}z_{jt}}{\sum_i z_{it}^2},
\qquad
H_{ab}=\frac{1}{S_0}\sum_{ij}w_{ij}z_{ia}z_{jb}.
\]

Moran's I 衡量同一 Topic 的空间自相关。跨 Topic 的 \(H\) 在对称图上也对称；正值表示相邻位置的相对高值较常共同出现，负值表示空间排斥式关联。它不等于细胞接触概率，不涉及配体—受体，也不是细胞通讯强度。

随机标签零假设为：**在已观察到的图上，整个 spot 的 Topic 组成向量可在所有 spot 之间交换。** 每次使用同一个置换联合重排所有 Topic，保留 Topic 间同一 spot 内的相关及组成闭合；共 999 次，固定种子0，串行计算。该零假设破坏所有空间结构，未对组织层、位置梯度、测序深度、各向异性或局部组成分层进行条件化。

Moran 随机标签期望为 \(-1/(n-1)\)。跨 Topic 期望为
\(E(H_{ab})=-\sum_i z_{ia}z_{ib}/[n(n-1)]\)。双侧 Monte Carlo p 以相对对应期望的绝对偏离计算，采用 `(1 + extreme)/(B + 1)` 修正，最小 p 为0.001。Moran 在全部 Topic 内 BH；邻域检验在所有唯一 Topic 对（含相同 Topic 对角）内 BH，不把对称的重复单元当作额外独立检验。

### 输出与边界

`07A_spatial_knn_graph` 展示邻接图和每个点的度；`07B_Moran_I` 展示真实 Moran 统计及 BH 阈值；`07C_Topic_neighbor_association` 展示 \(H\) 和按上述检验家族校正的星号。对角的同 Topic 关联与 Moran 共享信息，并非两份独立验证。

`07D_descriptive_distance_decay` 将所有唯一 spot 对按欧氏距离等宽分箱，展示每个 Topic 标准化值乘积的均值及每箱 spot 对数量。不同 pair 共享 spot，不独立；该图没有把 pair 当作独立样本计算 p 值或置信区间。距离衰减仅支持描述性的空间结构观察。

`results/neighborhood/` 保存边列表、距离、节点度、完整统计表、参数和全部置换零分布。组织分层本身可导致非常显著的空间检验；组成闭合也可产生负相关。跨 Topic 显著邻域关联不能单独证明相互作用、通讯、因果关系或细胞命运转换。正式研究应结合组织学与参考细胞注释，预先确定邻域尺度和受限置换方案，再以独立重复或实验验证。

## 验收与复用 / Validation and reuse

| 状态 | 含义 |
|---|---|
| `PASS` | 对指定官方示例已实际运行、输出并校验，不扩大到新数据或完整论文实验 |
| `PARTIAL` | 有实际输出，但仅覆盖已声明的部分数据/图件/数据库 |
| `BLOCKED` | 数据、依赖或官方服务不可用；日志有具体原因；没有伪造替代结果 |
| `NOT_RUN` | 只完成代码或未执行；语法通过不等于分析通过 |

在新的真实项目中，首先由研究者确认物种、ID、平台坐标单位、QC/选基因与 K、独立重复、计划检验家族及科学问题。上述模块保留的是可读、可修改的方法骨架，不预设任何种植体周围炎或其他正式队列结果。
